# Security Policy

## Supported Versions
Pickie is pre-1.0; only the latest `main` branch is actively supported. Security fixes target the latest code unless otherwise noted.

## Reporting a Vulnerability
Please use private, responsible disclosure. Do not open public issues with sensitive details.

Preferred:
- If this repository is hosted on GitHub, use “Report a vulnerability” (Security → Advisories → Report a vulnerability) to contact the maintainers privately.

Alternative:
- If private reporting is unavailable, please contact the maintainer privately to request a secure channel for details.

When reporting, include where possible:
- Affected component(s) and version/commit
- Impact and severity
- Steps to reproduce or a minimal proof-of-concept
- Any proposed mitigations or workarounds

Acknowledgement & timelines:
- We aim to acknowledge new reports within 2 business days.
- You’ll receive a preliminary assessment and an estimated timeline for a fix.
- We coordinate disclosure and attribution once a fix or mitigation is available.

## Scope
This policy covers the Pickie source code in this repository. Vulnerabilities in third‑party dependencies should be reported upstream to their respective maintainers.

## Safe Harbor
We support good‑faith security research. If you comply with responsible disclosure and avoid privacy violations, data destruction, or service disruption, we will not pursue legal action.
